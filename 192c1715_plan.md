# Sales & Promotions Implementation Plan

## Current Snapshot
- `Controllers/StaffController.cs` already exposes JSON endpoints for Stock/ManageUsers and renders the `Sales()` view but still returns placeholder markup. This is where new Sell-specific actions will live.
- `Views/Staff/Sales.cshtml` is only a static stub, while `Views/Staff/Stock.cshtml` and `Views/Staff/ManageUsers.cshtml` demonstrate the layout + inline JS pattern to follow.
- Data needed for this feature already exists in `Models/db/Coupon.cs`, `Order.cs`, `OrderItem.cs`, `ProductVariant.cs`, and related EF mappings in `Models/db/ShoeStoreContext.cs`.
- `Services/CheckoutService.cs` shows how domain services encapsulate data logic and how coupons are validated, providing a reference for structuring a Staff-focused analytics service.

## Implementation Plan

### 1. Sales DTOs & ViewModels (`ViewModels/Staff/SalesViewModels.cs`)
- Create a new file to hold Sell-area models:
  - `SalesDashboardViewModel` supplying month/year dropdown data, default scope (`monthly`), `DefaultYear`, `DefaultMonth`, and serialized options for the Razor view.
  - `CouponRowViewModel`, `CouponUpsertRequest` (DataAnnotations for code/percent/min purchase/date range), and `CouponDeleteRequest`.
  - `SalesSummaryQuery` (scope, year, optional month) plus helpers to clamp inputs to the latest three years.
  - `SalesSummaryResult` with `SalesSummaryCardViewModel` (totals for revenue/orders/avg order/coupon usage/discounts) and `SalesTrendPointViewModel` (label, order count, revenue).
  - `TopProductRowViewModel` capturing rank, product name, category, thumbnail, quantity sold, and revenue.
- Keep types serializable for JSON responses (`System.Text.Json` friendly) and reuse decimal rounding helpers for display strings.

### 2. StaffSalesService (`Services/StaffSalesService.cs`)
- Add a scoped service injected with `ShoeStoreContext` to isolate Sell analytics/CRUD logic.
- Coupon APIs:
  - `GetCouponsAsync()` returns all coupons ordered by `StartDate` (desc) with derived fields (`UsageCount`, `IsActive`, `StatusLabel`).
  - `CreateCouponAsync(CouponUpsertRequest)` and `UpdateCouponAsync(int id, CouponUpsertRequest)` normalize `CouponCode` (trim + uppercase) validate uniqueness, ensure `StartDate <= EndDate`, convert optional decimal inputs to `null` when <= 0, and persist via EF.
  - `DeleteCouponAsync(int id)` prevents deleting coupons that already have orders (optional: block or allow with warning).
- Sales analytics:
  - Helper `ResolveDateRange(SalesSummaryQuery)` returns `(startUtc, endUtc, scope)` ensuring yearly view stays within current year and two previous years.
  - `GetSalesSummaryAsync(SalesSummaryQuery)` filters `_context.Orders` by `CreatedAt` range and `Payments.Any(p => p.PaymentStatus == "Paid")`.
    - Compute totals: `TotalOrders`, `TotalRevenue = Sum(FinalAmount ?? 0)`, `DiscountTotal`, `CouponOrders`, `AverageOrderValue`.
    - Build `Series`:
      - Monthly: group orders by day-of-month (1..DaysInMonth), summing revenue and counts, include zero rows for missing days.
      - Yearly: group by month (1-12) for selected year; include zeroed months to keep chart consistent.
  - `GetTopProductsAsync(SalesSummaryQuery, int limit = 5)` joins `OrderItems` → `Order` → `ProductVariant.Product`, applies the same date/payment filters, groups by product, then returns the top N by quantity (tie-breaking by revenue).
- Service returns strongly typed view models for controller JSON responses.

### 3. Controller Updates (`Controllers/StaffController.cs`)
- Inject `StaffSalesService` and store as `_staffSalesService`.
- Update `Sales()` action to pass a populated `SalesDashboardViewModel` (build month list via `CultureInfo("en-US")` or `th-TH`, year list = current year + previous two). Keep `CanAccessSection("Staff Sell")` guard.
- Add Sell-only endpoints (decorate with `[Authorize(Roles = "Admin,Staff Sell")]` and `[IgnoreAntiforgeryToken]` on POSTs for AJAX parity with other staff tools):
  - `Task<IActionResult> ListCoupons()` → `Json(new { success = true, data })`.
  - `Task<IActionResult> CreateCoupon([FromBody] CouponUpsertRequest request)` / `UpdateCoupon(int id, ...)` / `DeleteCoupon([FromBody] CouponDeleteRequest request)` returning success + refreshed row or error message.
  - `Task<IActionResult> SalesSummary([FromQuery] SalesSummaryQuery query)` returning `SalesSummaryResult`.
  - `Task<IActionResult> TopProducts([FromQuery] SalesSummaryQuery query, [FromQuery] int limit = 5)` returning ranked list.
- Follow existing error-handling pattern (ModelState errors -> `Json(new { success = false, message = ... })`).

### 4. Dependency Registration (`Program.cs`)
- Register the new service: `builder.Services.AddScoped<StaffSalesService>();`.
- No other startup changes required.

### 5. Razor View (`Views/Staff/Sales.cshtml`)
- Replace placeholder with:
  - Hero block describing Sales & Promotions and action buttons (refresh/export placeholder).
  - Filter toolbar: `select` for scope (monthly/yearly), year dropdown (current & previous 2), conditional month dropdown (1-12).
  - Summary card grid (Total Revenue, Orders, Avg Order, Coupon Usage, Discount Given) bound to JS-populated spans.
  - Chart card containing `<canvas id="salesTrendChart">` and fallback text.
  - Top products card/table mirroring stock table styling, showing product info, quantity, revenue, and share.
  - Coupon management card with table + toolbar buttons (`#addCouponBtn`, `#refreshCouponsBtn`), columns for code, discount, min spend, validity period, status, usage count, and actions (Edit/Delete).
  - Modal dialog for Add/Edit coupon (shared form) and Delete confirmation modal; mimic modal markup from `Views/Staff/ManageUsers.cshtml`.
- Keep styles in `@section Styles` with BEM-ish classes reused by script hooks.

### 6. Client-Side Logic (`Views/Staff/Sales.cshtml` @section Scripts)
- Define `window.salesConfig` with endpoints from `Url.Action`, default filters (`Model.DefaultYear`/`DefaultMonth`), and serialized month/year options for JS.
- Load Chart.js via CDN (e.g., `https://cdn.jsdelivr.net/npm/chart.js`) before custom script.
- Implement an IIFE similar to ManageUsers:
  - Manage state: `filters`, `summary`, `coupons`, `topProducts`, `editingCouponId`.
  - Helpers: `buildQueryString(filters)`, `formatCurrencyTHB`, `formatDateRange`, `showToast`.
  - `loadSummary()` fetches `/Staff/SalesSummary`, updates card text, toggles loading classes, and feeds Chart.js dataset (line/area). Handle zero data by showing placeholder message.
  - `loadTopProducts()` populates table rows and handles empty states.
  - `loadCoupons()` populates coupon table with action buttons; highlight expired/active via badge classes.
  - Form handlers for `Add`/`Edit` share validation, convert `input type="date"` to ISO strings, send JSON to create/update endpoints, then refresh list + summary.
  - Delete flow prompts for confirmation and POSTs to delete endpoint.
  - Filter dropdown change events refetch summary + top products (month dropdown disabled when yearly).
  - Buttons for manual refresh (coupons, analytics) reuse the same loaders.

## Testing Strategy
1. `dotnet build` to ensure the solution compiles after adding new service, DTOs, and Razor changes.
2. `dotnet test` (if tests exist) for regression coverage.
3. Manual QA:
   - Run `dotnet run`, log in as a Staff Sell user, open `/Staff/Sales`.
   - Verify default monthly summary renders values & chart, and that switching to yearly updates data/visibility of month selector.
   - Test coupon CRUD: create with valid/invalid inputs (duplicate codes, reversed date range) and confirm validation feedback surfaces.
   - Confirm deleting coupons with linked orders behaves per service rules.
   - Place sample orders (via checkout) spanning multiple months; verify they appear in summary totals and top products after selecting matching filter windows.
4. Spot-check JSON endpoints (e.g., browser devtools or curl) to ensure schemas match the JS expectations for summary, top products, and coupons.
